# TODO V1 要件定義書

授業で Fetch と REST API の対応を確認するため、受講者が架空の TODO を登録し、完了・未完了を切り替え、削除できるようにする。既存の Express・TypeScript・EJS サイトに追加し、トップ、DB 接続確認、商品一覧を引き続き利用できること。

| ID・操作 | 入力・結果 | 受け入れ条件と確認方法 |
| --- | --- | --- |
| REQ-01 一覧 | 画面を開くと GET で ID 昇順の一覧を取得する。 | 200、配列を返す。0件なら `data: []` かつ画面は「TODOがありません」。複数件はID順と照合する。 |
| REQ-02 登録 | タイトルの前後の空白を取り、1〜100文字なら未完了で保存する。 | POST が201、採番したID、正規化したタイトル、完了状態false、作成日時を返す。再読み込みして残る。欠落・型違い・壊れたJSONは400、空白のみ・101文字は422。 |
| REQ-03 部分更新 | 対象IDと真偽値 `isCompleted` を送り、完了状態だけを変更する。 | PATCH が200。チェックを入れる・外すと対象だけが変わり、タイトル・作成日時は不変。不正なID・空本文・型違いは400、未登録IDは404。 |
| REQ-04 削除 | 対象IDを指定して削除する。 | DELETE が204で本文なし。再取得で対象が消える。不正なIDは400、同じIDの再削除は404。 |

IDは1以上の整数。画面は処理中・入力不備・通信失敗を区別し、タイトルをHTMLとして解釈しない。通常の操作はページ全体を再読み込みせず一覧を更新する。

GET・POST・PATCHの成功時は `{"status":"success","data":...}`。エラー時は `{"status":"error","code":"...","message":"...","details":[]}` とし、内部障害は500、DB接続不可は503。接続文字列やSQLは返さない。

ローカル・Vercel Preview・マージ後のProductionで同じ4操作、異常系、既存画面を確認する。Neonは共有なので、各試験では架空のタイトルと自分が作成したIDだけを使う。認証、優先度、絞り込み、タイトル変更はV1の対象外。公開画面には個人情報や重要な予定を入力しない。
